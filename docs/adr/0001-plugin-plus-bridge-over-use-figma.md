# Figma plugin + local bridge instead of use_figma

Copying a Pen frame used to go through an LLM: it read the node JSON from the Pen MCP, wrote it to disk, then retyped a ~50 KB generated script into the Figma MCP's `use_figma` tool. The model's output tokens were the bottleneck (minutes and ~25k tokens per frame). We moved the model out of the data path entirely: a background bridge on the Mac talks to Pen's own MCP server binary over stdio, and a private Figma development plugin fetches the Pen JSON from the bridge over localhost and builds the nodes itself.

## Considered Options

- **Script calling `use_figma` directly (no LLM).** Rejected: payload still has to be inlined as code under a ~50k-char cap, daily call quotas, and unclear whether a non-approved MCP client can authenticate or whether the code can see the user's selection/viewport.
- **Terminal command per copy.** Rejected in favour of an always-on bridge so the user works entirely from the plugin panel and the Pen connection stays warm (Pen's MCP server needs ~2 s after start before it answers).

## Consequences

- Works only in the Figma desktop app (development plugins can reach localhost only there), and the plugin must be opened once per Figma session.
- The bridge is a LaunchAgent; requests must carry a shared key generated by `pen2figma install`, because any local web page could otherwise read client designs from it.
